# Сборка текущей концепции v5

Литературный источник: manuscript/source.md, редакция v4. Дизайн v5 задан в build_layout_v5.py в миллиметрах, независимо от пагинации Word. Он создает общий мастер exports/current/layout-v5.json для Word и Figma. Исторические скрипты v3/v4 сохраняются для воспроизведения прошлых версий.

## Зависимости и шрифты

Зависимости Python указаны в requirements.txt. Для измерения набора нужны PT Serif и IBM Plex Sans с кириллицей: см. assets/fonts/README.md. Задать BOOK_FONTS или поместить файлы в assets/fonts/. Для рендера и чтения Word установить эти семейства системно. Они не встроены в DOCX; подмена шрифтов меняет переносы.

## Сборка Word

```bash
python tools/build_layout_v5.py
python tools/build_docx_v5.py
python tools/book_audit.py
```

Результат: exports/current/Почему_так_первые_пять_глав_v5.docx. Формат 190 × 250 мм. Основной набор PT Serif 11/14,8 пункта, в узких вводных колонках 10,5/14; заголовки IBM Plex Sans. В Word текст остается редактируемым в привязанных к странице блоках, изображения и фигуры отдельные. Это фиксированная композиция для просмотра концепции. Значительное изменение текста требует переверстки, автоматического потока между всеми блоками нет. Нельзя заменять источник непрочитанным экспортом или перегенерировать поверх новых авторских правок.

Строки измеряются в мастер-скрипте, ширина текстовых контейнеров Word и Figma получает допуск 1,5 мм для различия метрик рендереров. После правок проверять фактические переносы и границы. Номера оглавления заданы в master-сценарии; сверять их с реальными началами глав после каждой перепагинации.

Дополнительные визуальные комментарии автоматически сохраняются в manuscript/visual-notes-v5.md. Основной source.md при переверстке не изменяется. После содержательной правки исходника также запустить update_preview.py для читаемой Markdown-версии.

## Иллюстрации

Четыре сцены imagegen сохранены в assets/figures/v4_*.png; сведения о генерации в assets/photos/generation-v4.json. Точные сравнения берутся из diagrams-v4.json и задаются отдельными слоями. Малые SVG для Word растрируются PyMuPDF, для Figma остаются векторами. Кадр стула вырезан из того же изображения; новый кадр не генерировался.

## Figma

Идентификаторы текущего результата: exports/current/figma-v5.json. Файл 3tFcd527exTT53dlDQkl5R, страница 17:60, корневой фрейм 17:61. 33 полосы объединены в 17 фреймов, включая одиночный титул. Масштаб: 2 Figma px на типографский пункт; физический размер задан отдельно в миллиметрах.

render_figma_v5.js является телом вызова Figma Plugin API. Ему передаются bookPages из мастера и pageIds: номер полосы → ID заранее созданного пустого фрейма. Целевая страница и хеши четырех существующих изображений привязаны к этому Figma-файлу. Для нового файла сначала создать пустые полосы и получить актуальные ID и хеши. Не запускать повторно поверх заполненных фреймов: защитная проверка прекращает запись. Текст получает auto-layout-контейнер с фиксированной шириной и автоматической высотой. Точные схемы редактируются как текст и векторы. Координаты не извлекаются из PDF Word.

## Проверка и границы результата

Word отрендерен в PDF и PNG для внутренней проверки; просмотрены все 33 страницы. В Figma просмотрены все 17 фреймов. Сверены 403 текста, однократное использование 160 исходных блоков, 14 номерных иллюстраций, подписи, пагинация и границы. Отчеты: exports/current/validation-v5.json и figma-validation-v5.json; карта визуальной проверки: design/LAYOUT-V5-REVIEW.md.

При повторной сборке использовать новую папку рендера, чтобы не смешать версии. После любых геометрических правок экспортировать и проверить затронутые страницы и полноту итогового файла. Рендеры PDF/PNG не являются пользовательской поставкой.

book_audit.py проверяет целостность источника, маркеры, файлы, alt, записи прав, повторы и выбранные символы. Результат: 0 ошибок и 14 предупреждений о незавершенной проверке прав. Это не литературная оценка и не допуск в печать. Авторское одобрение, распечатка 1:1, раскрытие, цвет и производственный preflight пока не получены.
