# Инструменты для редакторской и визуальной работы

Проверка открытых источников: 1 ноября 2026 года. Рекомендации относятся к «Почему так». Здесь указана пригодность по документации, а не результаты полного тестирования сторонних программ. Бесплатность локального инструмента не означает бесплатность связанного облака. Доступность сервисов и оплаты из России отдельно не проверена.

## Набор для ближайшего этапа

| Задача | Выбор | Почему |
| --- | --- | --- |
| Хранить исходник и историю | Текущий mybook с Markdown | Уже работает, не требует миграции и сохраняет изменения |
| Получать авторские и редакторские правки | Word с исправлениями и комментариями | Удобный обмен с редактором; исходник обновлять только после сверки правок |
| Учитывать источники | Zotero плюс реестр конкретных утверждений | Библиография и проверка факта решают разные задачи |
| Проверять техническую целостность | tools/book_audit.py | Локальная проверка без передачи текста во внешний сервис |
| Проверять русский текст | Академос, Грамота; LanguageTool как помощник | Правило можно проверить; автоматическую правку нужно оценивать в контексте |
| Проектировать развороты | Figma для прототипа | Знакомая автору среда, удобно сравнивать варианты; печатная подготовка требует отдельного процесса |
| Верстать бумажную книгу | InDesign, если доступен в рабочем процессе редакции; иначе рассмотреть Affinity Layout или Scribus | Выбирать после проверки экспорта, шрифтов, совместной работы и требований производства |
| Готовить электронную версию | Pandoc/Quarto для сборки, Sigil при необходимости ручной доводки | Это отдельная версия с собственной проверкой |
| Проверять EPUB | EPUBCheck, Ace, реальные читалки | Проверка формата, доступности и поведения на устройстве дополняют друг друга |

## Навыки и лицензии

Подробный отбор есть в основном отчете. Для технических репозиториев сохранен [снимок метаданных](repositories.json): ссылка, ветка, отметка архивирования, дата последнего push и то, что API сообщает о лицензии. Это проверка происхождения, не аудит безопасности и не гарантия поддержки.

У editorial-skills лицензия не подтверждена; у author-toolkit API вернул NOASSERTION. Такие результаты не означают «можно копировать». В anthropics/skills документные модули имеют отдельные условия source-available. Идеи процесса изложены своими словами, сторонний код и полные тексты навыков в книгу не перенесены.

У Bookwright полезен постоянный контекст, но его стартовый режим требует интервью даже при уже известных данных. У book-writing-skill интересны проверки PDF, но обязательная схема главы и ограничения на пунктуацию не являются требованиями издателей. У Humanizer полезны диагностические признаки, но нет доказательства, что их применение само по себе улучшит нашу книгу.

## Собственный навык проекта

«Книга Почему так» связывает текущий контекст, литературную редактуру, визуальный сценарий, заявку и проверку производства. Он использует сведения проекта, не назначает чужие шаблоны обязательным стилем и не отправляет материалы издателям. Результаты автоматических и модельных проверок всегда отделяет от реакции реальных читателей.

Навык [установлен](https://chatgpt.com/skills?skill_id=6ae737d6ac50819189e6c7c7ba8deaa1), прошел проверку структуры и отдельное практическое задание на текущем пилоте. Инструкции проекта также сохранены в rules/ и остаются доступны независимо от установленного навыка.

## Что реально проверено в этой работе

Сторонние инструменты исследованы по первичным страницам, документации и выбранным исходным инструкциям. Локально используются уже доступные Git, Python, Pillow, Pandoc и средства чтения PDF. Новый book_audit.py запускается на текущем исходнике и на тестовых случаях; результаты фиксируются в отдельном аудите. Полный производственный цикл InDesign/Scribus/Affinity/Typst/EPUB в рамках этого исследования не запускался.
